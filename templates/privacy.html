PRIVACY ARCHITECTURE

Built to make control obvious.

This page describes how this local Lunelle build handles data. It is a technical overview, not a substitute for a lawyer-reviewed privacy policy if you commercialize the product.

01

Local database

Account, cycle, journal and wellness records are stored in the Lunelle SQLite database on the machine running this app.

02

Password hashing

Passwords and optional PINs are stored as secure hashes through Werkzeug rather than plain text.

03

Private PWA behavior

The service worker is designed not to cache authenticated health screens for offline reading.

04

Portable data

Users can export CSV data and download a JSON backup from the command palette or account settings.

05

Delete controls

Tracked data can be cleared from settings. Commercial deployment should add a complete account deletion flow and retention policy.

06

Before public launch

Use HTTPS, a production WSGI server, CSRF protection, verified password recovery, database encryption strategy, and legal/privacy review.
